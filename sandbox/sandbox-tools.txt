CDDC SANDBOX PLACEHOLDER TOOLING
================================

This image is intentionally staged. Web and crypto are implemented; the other
lane layers are still placeholders.

Build:
  docker build -f sandbox/Dockerfile.sandbox -t cddc-sandbox sandbox

Build one stage:
  docker build -f sandbox/Dockerfile.sandbox --target pwn -t cddc-sandbox:pwn sandbox

Run:
  docker run --rm -it -v "$PWD:/challenge" cddc-sandbox

LAYERS
------

base
  Present now:
    ubuntu, python3, pip, venv, git, curl, wget, file, jq, xxd, zip/unzip
  Purpose:
    Common OS/runtime layer for all challenge work.

web
  Present now:
    nodejs, npm
  Purpose:
    JavaScript/npm workflows for web challenges.

crypto
  Present now:
    sagemath, hashcat, john, openssl, pari-gp
    pycryptodome, gmpy2, sympy, z3-solver, fpylll
    RsaCtfTool at /opt/RsaCtfTool
  Purpose:
    Math/CAS workflows, RSA automation, cracking helpers, and Python crypto
    scripts.

pwn
  Placeholder for:
    gdb, ltrace, strace, binutils, gcc/g++, make, cmake, patchelf
    pwntools, ropgadget, capstone, unicorn

rev
  Placeholder for:
    radare2/rizin, angr, lief, pyelftools, Java for Ghidra headless
    optional mounted commercial/free reversing tools

forens
  Placeholder for:
    binwalk, exiftool, foremost, sleuthkit, testdisk
    pngcheck, imagemagick, ffmpeg, sox, zsteg, volatility3

ai
  Placeholder for:
    numpy, scipy, scikit-learn, CPU torch, keras, transformers, datasets

NOTES
-----

- Keep each layer small until a lane actually needs the tools.
- Prefer apt packages for stable CLI tools and pip packages for Python helpers.
- Heavy tools like SageMath, PyTorch, Ghidra, and hashcat should be added
  deliberately because they dominate image size/build time.
- /challenge is the intended working directory.
