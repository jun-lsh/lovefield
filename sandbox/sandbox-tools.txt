CDDC SANDBOX PLACEHOLDER TOOLING
================================

All layers are implemented. Lighter/more-shared lanes sit low (every higher target
inherits them); heavy/niche lanes sit high so a lean `--target` stays small.

Chain: base -> recon -> harness -> crypto -> web -> stego -> pwn -> rev -> forens -> ai

Build:
  docker build -f sandbox/Dockerfile.sandbox -t ctf-sandbox sandbox

Build one stage (e.g. a lean triage box, or a specialist target):
  docker build -f sandbox/Dockerfile.sandbox --target recon -t ctf-sandbox:recon sandbox
  docker build -f sandbox/Dockerfile.sandbox --target pwn   -t ctf-sandbox:pwn   sandbox

Run:
  docker run --rm -it -v "$PWD:/challenge" ctf-sandbox

LAYERS
------

base
  Present now:
    ubuntu, python3, pip, venv, git, curl, wget, file, jq, xxd, zip/unzip, tmux
    docker client + compose v2 plugin (client only, no daemon)
    docker shim (cddc-docker-shim) shadowing `docker` for per-challenge labeling
  Purpose:
    Common OS/runtime layer for all challenge work. The docker client is inert
    unless the bot binds the host /var/run/docker.sock into the sandbox (gated to
    non-triage roles, CDDC_DOCKER_SOCK) - then the agent can `docker compose up` a
    service challenge against the host daemon (docker-out-of-docker). The shim
    auto-labels manual `docker run`/`create` with cddc.thread=$CDDC_THREAD so the
    host reaps the sibling containers per challenge even without compose; the real
    client lives at docker.real and the shim is a no-op when CDDC_THREAD is unset.

recon
  Present now:
    binutils (strings/objdump/nm/readelf), gcc, g++, make, libc6-dev
    checksec, patchelf, radare2
  Purpose:
    Cross-cutting TRIAGE tooling - compile, disassemble, checksec, and take a
    quick decompile glance to assess and route a challenge. Sits directly above
    base so every higher target inherits it; a triage box can build `--target
    recon` (or harness) without dragging in the heavy specialist layers. Heavy
    lane depth (pwntools, angr, Ghidra, volatility3, torch) stays in pwn/rev/
    forens/ai, NOT here.

crypto
  Present now:
    sagemath, hashcat, john, openssl, pari-gp
    pycryptodome, gmpy2, sympy, z3-solver, fpylll
    RsaCtfTool at /opt/RsaCtfTool
  Purpose:
    Math/CAS workflows, RSA automation, cracking helpers, and Python crypto
    scripts.

web
  Present now:
    nodejs, npm (from harness), dnsutils, go
    pip: requests, httpx, beautifulsoup4, lxml, pyjwt, flask, websocket-client, name-that-hash
    jwt_tool (/usr/local/bin/jwt_tool)
  Purpose:
    Jeopardy web: craft a precise request + analyze the response, host an OOB
    listener (flask), tamper JWTs. NO scanners/brute-forcers (sqlmap/ffuf/nuclei/
    nmap) - that's pentest tooling, ill-suited to jeopardy. Sits above crypto so
    a lean `--target crypto` build avoids web-specific tooling.

stego
  Present now:
    steghide, stegseek (fast cracker), outguess, zsteg (gem), binwalk, foremost
    exiftool, imagemagick, ffmpeg, sox, pngcheck, zbar-tools, qrencode, tesseract
    ruby, p7zip; pip: pillow, numpy, matplotlib, stego-lsb
  Purpose:
    Lightweight stego + media forensics. Sits BELOW pwn/rev so a stego box stays
    lean (no Ghidra/.NET/angr). Heavy disk/memory/Windows forensics is in `forens`.
    ruby lives here (zsteg); pwn inherits it for one_gadget/seccomp-tools.

pwn
  Present now:
    gdb (+ gdb-multiarch, gdbserver), strace, ltrace, socat, netcat-openbsd
    gcc-multilib, qemu-user-static, qemu-system-x86, cpio (kernel pwn), ruby
    pip: pwntools, angr, angrop, ROPgadget, ropper, capstone, unicorn, keystone-engine
    gems: one_gadget, seccomp-tools
    bata24/gef at /opt/gef (system gdbinit); pwninit at /usr/local/bin
    /opt/glibc-all-in-one + /opt/libc-database (libc fetch/ID; DBs on demand)
  Purpose:
    Binary exploitation: debug, trace, ROP, symbolic exec, and libc-matching.
    (binutils/gcc/patchelf/radare2 come from recon.) A pwn SPECIALIST also gets
    the docker socket -> `docker compose up` the challenge for the exact libc/ld.
  Agents fill gaps at runtime (pip/apt/gem inside the container).

rev
  Present now:
    Ghidra 12.1 headless (ghidra-headless) + GolangAnalyzer 1.3.0 extension
    ghidra-rpc - Ghidra-as-a-JSON-daemon, the agent's decompile interface
    pip: lief, pefile, pyelftools, frida-tools, qiling, uncompyle6, flare-floss
    pycdc/pycdas (py3.9+ bytecode), jadx (Android), ilspycmd (.NET, via dotnet-sdk-8.0)
    apt: openjdk-21, apktool, upx, cmake, gcc cross (aarch64/arm)
    (radare2 from recon; angr/capstone/unicorn/keystone from pwn)
    oxidizer (Rust decomp): repo at /opt/oxidizer, run as a container via the socket
  Purpose:
    Decompilation, emulation, dynamic instrumentation, .NET + Android + Go + Rust.
  Note: when forens is reordered below pwn/rev, .NET + ilspycmd move down to forens
    (shared with Eric Zimmerman tools) and rev inherits them.

forens (HEAVY - disk / memory / Windows, above rev)
  Present now:
    apt: sleuthkit, testdisk, tshark, pcapfix, ntfs-3g
    pip: volatility3
    Eric Zimmerman (.NET 9): MFTECmd/EvtxECmd/RECmd baked best-effort; net9 runtime
      installed. Pull more / re-pull via Get-ZimmermanTools - see /opt/cddc-forens.txt
  Purpose:
    Disk images, memory dumps, pcaps, Windows artifacts. Light stego/media
    carving lives in the `stego` layer (below pwn/rev), not here.

ai (top of chain - heaviest, ISOLATED venv)
  Present now:
    venv at /opt/ai-venv - run with `ai-python` (NOT system python3):
      torch + torchvision (GPU/CUDA default; --build-arg TORCH_VARIANT=cpu to slim),
      scipy, scikit-learn, pandas, transformers, safetensors
    apt: libgomp1
  Purpose:
    ML/LLM challenges, isolated so its modern numpy/scipy never clash with Sage's
    1.x in the system python. GPU when the host exposes one (CDDC_SANDBOX_GPU=1 ->
    docker --gpus all, needs nvidia-container-toolkit); CPU fallback otherwise.
    Only --target ai / the full image pays for the weight.

harness
  Present now:
    claude: native install at ~/.local/bin/claude (via claude.ai/install.sh)
    codex:  npm -g @openai/codex
    non-root user `ctf` (some CLIs refuse to run as root)
  Purpose:
    The harness worker (CDDC_WORKER=harness) runs these CLIs in a tmux session
    via `docker exec`, driven from the host by libtmux. The API key is passed
    through at exec time (-e ANTHROPIC_API_KEY / -e OPENAI_API_KEY), never baked
    into the image.

NOTES
-----

- Keep each layer small until a lane actually needs the tools.
- Prefer apt packages for stable CLI tools and pip packages for Python helpers.
- Heavy tools like SageMath, PyTorch, Ghidra, and hashcat should be added
  deliberately because they dominate image size/build time.
- /challenge is the intended working directory.
